# 红外折叠与双轴跟随串联

主流程位于 `applications/infrared_pitch_auto.cpp`。入口复用现有homing任务，后续调用原pitch_start任务和trajectory_follow任务。没有新增、删除或改动FreeRTOS任务配置，也没有修改原始轨迹数据。

## 开关与顺序

`control_constants.hpp` 的 `INFRARED_PITCH_AUTO_ENABLE=true` 启用本流程，优先于旧的测试选择开关。设为false后，原homing、独立pitch_start、单yaw、单pitch和双轴测试选择恢复原路径。原有PID与跟随参数保留。

1. 等待板载IMU静态校准完成，等待三台电机反馈。期间不驱动电机。
2. 复用队友homing的6020后靠堵转判据，2006零电流。后靠完成时记录2006输出轴编码器零点。
3. 2006驱动至队友的默认姿态。其程序参数实际为25°，保留在本模式专用参数中，未覆盖旧程序20°参数。默认姿态等待有效红外距离≤40cm，保持队友原有pitch弱保持与yaw保持行为。
4. 继续队友的2006运动，到相对输出轴编码器2.2rad的下降姿态，保留5秒停留及6020弱保持。
5. 回折运动直接采用队友homing相同的驱动力矩和速度阻尼公式：`-dir * HOME_M2006_DRIVE_DIR * HOME_M2006_PULLBACK_TORQUE_NM - HOME_M2006_DAMPING_NM_PER_RAD_S * 实际转速`。回转力矩1.0Nm、阻尼0.30Nm/(rad/s)与队友一致，不加入新的速度规划。2006输出轴相对编码器从大于0.8rad回到0.8rad时，切换固定0.8rad闭环保持，取消“反转固定5秒后释放”。到位容差0.015rad，速度≤0.05rad/s持续200ms视为稳定。保持目标不随外力或下垂重新捕获。
6. 从首次有效≤40cm识别开始累计20秒，同时必须已经回折稳定。任一条件未满足就继续保持/等待。随后交接到原pitch_start，从其初始化、后靠、IMU机构角1.07rad到位、强锁2006、3°预抬和参考对齐等完整准备流程执行。
7. yaw与pitch真正进入原始轨迹跟随后开始新的5秒计时。到5秒停止轨迹，捕获当时两轴IMU角度，切换弱位置保持；2006保持原pitch_start强锁，不释放、不重新捕获目标。两轴评分停止累计并保留最终值。

这是每次上电执行一次的流程，红外反复接近、离开或短时失联不会重置计时、重新触发或重新启动轨迹。启动、通信、IMU、运动超时等已有故障路径仍生效，故障不自动重试。阶段12、故障码6表示超速停机；此时红外计时继续显示，但满20秒不会绕过故障交接。两轴8rad/s、连续50ms的原超速判据保持不变。

## 两套角度标准

- 回折0.8rad：2006减速箱输出轴多圈编码器相对后靠完成时的位置，36:1减速比。不是编码器绝对角，也不是IMU机构角。
- pitch_start当前1.07rad（以前曾为1.1rad）：依旧由IMU测量机构从后靠位置转动的角度，代码和参数不改。
- 两轴跟随、停止后的6020保持和评分：仍使用IMU角度；编码器仅供新前半段homing和2006保持使用。

## 红外计时与接口适配

队友的 `infrared_timer_ms` 在 `shared_data.hpp`，实际是累计时间而非时间戳。原代码homing用40cm触发，计时却用30cm。本次统一为首次有效≤40cm识别，仅校验正确且测距有效的数据帧可启动计时。原始距离、帧校验、自动波特率和失效判断不改。

新模式前半段和原pitch_start共享CAN1 ID2 GM6020、ID1 M2006及ID4 yaw。CAN接收观察器不截走现有反馈；新模式在交接前独占发送，交接后不再发送旧指令，pitch_start在交接前禁止发送。避免0x1FE与0x200出现两个控制器交替覆盖。

保持队友前半段的yaw锁定增益12.6Nm/rad、阻尼0.18Nm/(rad/s)、上限0.95Nm，采用新模式专用常量，不用队友参数覆盖当前跟随PID。保留当前传感器、串口与CAN配置，没有导入队友的FreeRTOS、UART回调或传感器驱动。

## 参数位置

均在 `control_constants.hpp` 顶部 `INFRARED_AUTO_*`：

| 参数 | 当前值 | 意义 |
| --- | --- | --- |
| INFRARED_AUTO_TRIGGER_CM | 40 | 首次红外识别阈值，cm |
| INFRARED_AUTO_PREPARE_DELAY_MS | 20000 | 首次识别至允许开始pitch_start的等待时间 |
| INFRARED_AUTO_FOLD_ENCODER_RAD | 0.8 | 回折时2006输出轴相对角 |
| INFRARED_AUTO_FOLD_KP/KI/KD | 10 / 2 / 0.30 | 前半段0.8rad保持参数，不影响原pitch_start |
| INFRARED_AUTO_FOLLOW_MS | 5000 | 两轴真正进入跟随后运行时长 |
| INFRARED_AUTO_WEAK_YAW_MAX_NM | 0.35 | 最后yaw弱保持力矩上限 |
| INFRARED_AUTO_WEAK_PITCH_MAX_NM | 0.35 | 最后pitch弱保持力矩上限，含现有重力补偿 |

最后弱保持继续受原有pitch边界制动约束。若仍有转速，电机需要一定减速过程，固定的保持目标不会跟着滑动而移动。

## Plot

保留四针UART2（代码USART1/huart1）、921600、8N1、Float32小端、18通道及 `AA BB 48` 帧格式。

| 通道 | 含义 |
| --- | --- |
| 1 / 2 | yaw目标 / IMU实际角，度 |
| 3 / 4 | pitch目标 / IMU实际角，度 |
| 5 / 6 | yaw / pitch评分系数 |
| 7 | 新流程阶段，见下表 |
| 8 | 新流程故障码，0正常 |
| 9 / 10 | 红外距离cm / 首次识别后累计秒数 |
| 11 / 12 | 2006输出轴相对角 / 前半段目标0.8rad |
| 13 / 14 | 2006指令 / 反馈电流换算力矩，Nm |
| 15 / 16 | 原pitch_start阶段 / 原跟随阶段（4为正常停止保持） |
| 17 | 本轮实际轨迹跟随时间，停止后固定5秒 |
| 18 | IMU校准进度0～1 |

若新流程发生超速（通道7=12且通道8=6），仅通道16/17/18改为锁存的故障证据：16=超速发生时的新流程阶段，17=GM6020 pitch转速(rad/s)，18=M2006输出轴转速(rad/s)。停机后的零转速不会覆盖这三个值；正常运行仍按上表输出。

通道7的阶段含义：0等待IMU，1等待电机反馈，2后靠，3默认姿态，4等待红外，5下降，6停留5秒，7回折，8回折保持等待计时，9原pitch_start准备，10双轴跟随，11结束后弱保持，12故障。

交接后通道11仍以首次后靠为原点记录编码器相对角，通道12的0.8只说明前半段目标；此时实际动作判据由pitch_start的IMU控制决定。

## 检查与边界

已对改变的源文件运行ARM目标语法和静态检查。使用实际控制器的constexpr测试覆盖计时边界、tick回绕、无效红外、初始化门槛、默认姿态、5秒停留、0.8相对编码器目标、稳定交接、受扰保持、抗积分饱和、故障停机与弱锁限幅。本次还校验了队友回转公式在不同位置/转速下的一致性、越过0.8rad后的制动保持，以及两轴超速判据和故障证据锁存。

另外编译检查关闭新模式后的homing、独立pitch_start、单yaw、单pitch、双轴和全关闭选择，以及新模式的优先级。尚未烧录到实物验证。终端中的GNU编译器无法启动，报Windows“无效的系统DLL重定位”，因此不能声称已完成GNU完整链接；请使用此前可正常构建的IDE进行最终编译烧录。
